# 不谢牌 · No Thanks! Web + CLI

这是一个 3–5 人《不谢牌》联机游戏。浏览器和 CLI 客户端连接同一个 Node.js 权威服务器，可在本机、局域网或通过 ngrok 公网游玩。

目前包含：

- 响应式 Web 牌桌，支持桌面端和移动端；
- CLI 房间、实时对局、对局导出和离线回放；
- 初级、中级、高级三种确定性人机；
- 基于 SSE 的实时房间状态和快捷聊天；
- Web 上传 JSON 回放，以及 Web/CLI 导出完整对局记录；
- 大厅规则页和房间内规则弹窗。

## 运行要求

- Node.js 18 或更高版本；
- 项目当前没有第三方 npm 运行依赖，无需安装数据库；
- 如需公网访问，另行安装并登录 ngrok。

## 本地与局域网启动

在项目目录运行：

```powershell
npm start
```

服务默认监听 `0.0.0.0:8787`：

- 本机浏览器打开 `http://127.0.0.1:8787`；
- 同一局域网的其他设备打开服务器电脑的局域网 IP，例如 `http://192.168.1.20:8787`；
- 如果局域网设备无法连接，请确认 Windows 防火墙允许 Node.js 接收入站连接。

可以通过环境变量修改监听地址和端口：

```powershell
$env:HOST = "0.0.0.0"
$env:PORT = "9000"
npm start
```

## Web 游玩

1. 输入昵称后创建房间，或从大厅加入仍在等待中的房间。
2. 房主创建房间后默认已准备；其他真人玩家需要点击“准备”。
3. 房主可以选择初级、中级或高级人机，也可以移除其他玩家。
4. 房间达到 3–5 人且所有玩家准备后，由房主开始游戏。
5. 对局中可以拒收、收牌或发送预设快捷语句；自己的标记数可见，其他玩家的标记数隐藏。
6. 牌局结束后可以查看计分、回放、导出 JSON，或让整个房间返回等待大厅继续下一局。

大厅可以查看完整规则；进入房间后也可以通过“查看完整规则”打开弹窗。快捷语句会显示在发送者头像旁约 5 秒，底部保留最近 3 条消息。

## CLI 游玩与回放

在另一个终端运行：

```powershell
npm run cli
```

CLI 主菜单可以创建房间、加入房间、刷新列表或回放本地 JSON。等待大厅中常用命令为：

- `ready` / `unready`：切换准备状态；
- `bot [beginner|intermediate|advanced]`：房主添加指定等级人机；省略等级时添加初级人机；
- `remove <玩家名称>`：房主移除玩家；
- `start`：房主开始游戏。

轮到自己时使用：

- `take`：收下当前牌和牌旁全部标记；
- `pass`：花费 1 个标记拒收；
- `chat <1-7>`：发送一条预设快捷语句。

连接其他服务器时，启动 CLI 前设置 `NO_THANKS_SERVER`：

```powershell
$env:NO_THANKS_SERVER = "http://192.168.1.20:8787"
npm run cli
```

已导出的记录无需连接服务器即可直接回放：

```powershell
npm run cli -- replay records\no-thanks-room-xxxx.json
```

也可以在 CLI 主菜单选择 `4. 回放本地 JSON` 并输入路径。回放命令包括 `next`、`prev`、`take`（跳至下一次收牌）、`end` 和 `quit`。

## 公网访问（ngrok）

ngrok 可以把本机游戏服务临时暴露到公网，无需公网 IP 或路由器端口映射。

先按“本地与局域网启动”运行 `npm start`，再打开另一个终端：

```powershell
ngrok http 8787
```

从输出中复制 `Forwarding` 后的 HTTPS 地址，例如：

```text
https://orange-example.ngrok-free.app -> http://localhost:8787
```

把 `https://orange-example.ngrok-free.app` 发给其他玩家，他们可以直接用电脑或手机浏览器加入。服务端不需要修改 `HOST` 或前端配置。临时隧道重新启动后，ngrok 可能分配新地址，应分享最新的 HTTPS 地址。

CLI 玩家使用同一个公网地址：

```powershell
$env:NO_THANKS_SERVER = "https://orange-example.ngrok-free.app"
npm run cli
```

当前原型没有账号登录、房间密码或管理后台，只应将 ngrok 地址分享给可信玩家。对局结束后在 ngrok 终端按 `Ctrl+C` 关闭公网隧道；关闭运行 `npm start` 的终端则会停止游戏服务。

## 游戏规则

- 3–5 人参加，每人初始有 11 个隐藏标记。
- 使用数字 3–35 的 33 张牌，随机暗置移除 9 张，剩余 24 张组成牌库。
- 随机选择起始玩家，并翻开牌库第一张牌。
- 当前玩家可以收牌，或者放置 1 个标记拒收；拒收后仍处理同一张牌，由下一位玩家行动。
- 收牌者拿走当前牌和牌旁全部标记，并继续处理新翻开的下一张牌。
- 没有标记时不能拒收，只能收牌。
- 所有已收的牌公开，但其他玩家的剩余标记数隐藏。
- 计分时，每组连续数字只计算其中最小的牌，再减去剩余标记数；最终总分最低者获胜。

例如持有 `4、14、15、16、30` 且剩余 10 个标记，牌分为 `4 + 14 + 30 = 48`，最终得分为 `48 - 10 = 38`。

详细规则参考：<https://gamesoncloud.blogspot.com/2013/04/nothanks.html>

## 实时同步、聊天与会话

浏览器和 CLI 都通过 SSE 长连接接收房间状态，不需要轮询等待其他玩家行动。快捷聊天使用独立的轻量 `quick-chat` SSE 事件；Web 发送者会先在本地乐观显示，其他客户端收到事件后立即更新。SSE 连接中断后，浏览器由 `EventSource` 自动重连，CLI 每隔 1 秒尝试重连。

服务端每 15 秒发送一次 SSE 连接保活注释。浏览器和 CLI 另外每 10 秒发送一次会话心跳，默认 30 秒未续租则会话失效；服务端每 5 秒清理一次过期会话。可以调整会话时长：

```powershell
$env:SESSION_TTL_MS = "60000"
npm start
```

浏览器房间凭证保存在当前标签页的 `sessionStorage`。刷新同一标签页可以继续会话，不同标签页不会自动共享玩家身份。关闭页面且心跳停止后，凭证最终会过期。

快捷聊天目前固定为 7 条白名单短语，每位玩家 1.2 秒最多发送一次。服务端最多保留最近 12 条，Web 和 CLI 展示最近 3 条；聊天不写入对局记录，也不传给人机 memory。受 CLI 输入模式限制，CLI 只能在轮到自己时发送快捷语句。

## 规则引擎与人机策略

`game-engine.js` 是独立的纯规则引擎，不依赖房间、HTTP、昵称或人机定时器，提供：

- `createGame(playerIds, options)`：创建一局游戏，可传入固定牌库或随机函数；
- `legalActions(state, playerId)`：获取当前玩家的合法动作；
- `applyAction(state, playerId, action)`：返回新的状态和公开规则事件，不修改输入状态；
- `score(cards, markers)`：按连续牌规则计算牌分、剩余标记和总分。

人机策略位于 `bot-strategies.js`。每个策略实现三个生命周期入口：

- `createMemory(matchSetup)`：开局创建策略自定义 memory；
- `onPublicEvent(memory, event)`：每次公开行动后更新 memory；
- `decide({ env, memory })`：使用固定环境和自有 memory 做纯函数决策。

服务端不读取或规定 memory 的字段。开局只传一次的 `matchSetup` 包含 `selfId`、固定行动顺序、初始标记数和牌库大小。每次决策的固定 `env` 包含从 0 开始的 `actionIndex`、从 0 开始的 `cardIndex`、当前牌、牌旁标记、自己的牌和标记，以及其他玩家的公开牌。公开行动事件包含行动者、动作、牌、操作前的牌旁标记及标记变化。

三种现有策略：

- 初级：只使用自己的牌、标记、当前牌和牌旁标记；优先收取可补齐或桥接连续段的牌。
- 中级：使用相同公开信息，但更早把标记视为稀缺资源，也会评估牌旁已经累积的标记。
- 高级：在中级基础上读取对手公开牌，并在自己的 memory 中根据公开 `pass/take` 事件维护标记账本；在自身代价可承受时阻止对手补齐或桥接连续段。

三个等级均为确定性策略，不读取未翻牌、暗置牌或牌库未来顺序。`bot-memory-utils.js` 提供行动距离和公开标记账本等可复用纯函数，策略可自行选择是否使用。

## 对局记录、导出与回放

每局开始时服务端保存可精确重放的初始状态；每次 `take/pass` 都记录行动者、动作、规则事件及行动者当时的合法决策观察。

Web 结果页支持：

- 查看每位玩家的连续牌段、牌分、剩余标记和最终总分；
- 上一步、下一步或跳至下一次收牌；
- 自动播放、暂停和 0.5× / 1× / 2× / 4× 倍速；
- 查看完整牌山以及当前回放到第几张牌；
- 下载完整 JSON 对局记录。

Web 大厅的“上传 JSON 并回放”可以直接载入已导出的记录，不需要服务器中仍存在原房间。CLI 在结束页输入 `export` 会将记录写入当前目录下的 `records/`；该目录已被 Git 忽略。

当前记录格式为 `schemaVersion: 1`，包含：

- `initialState`：含完整牌库的开局状态，用于精确回放；
- `turns`：从 0 开始编号的公开行动、规则事件和当时的决策观察；
- `result`：最终手牌、标记和计分结果。

每手 `observation` 刻意不包含后续牌库或暗置牌，只包含当时固定格式的决策环境和合法动作。对局记录不包含房间会话令牌。

## 测试

运行全部规则、人机、记录和牌桌布局测试：

```powershell
npm test
```

## 当前数据限制

房间、玩家会话、进行中的对局和可导出的记录都只保存在 Node.js 进程内存中，没有数据库持久化。服务器重启后这些数据会全部丢失；需要长期保存的对局应在结束后及时导出 JSON。

当房间内不再有真人玩家时，服务端会自动删除房间。大厅只列出仍有真人且尚未开始的房间。

## 主要文件

- `server.js`：HTTP API、房间、会话、SSE 广播和人机调度；
- `game-engine.js`：纯游戏规则；
- `bot-context.js`：人机固定环境、开局配置和公开事件；
- `bot-strategies.js`：现有三种人机策略；
- `bot-memory-utils.js`：可复用的人机 memory 工具；
- `game-record.js`：对局记录格式与生成；
- `cli.js`：CLI 联机客户端及离线回放；
- `public/`：Web 页面、样式、交互、快捷语句和牌桌布局；
- `test/`：自动化测试；
- `legacy/cpp/`：仅在本地保留的历史 C++ 版本和材料，已被 Git 忽略。

## 历史材料

原始 C++ 源码、旧版可执行文件和说明文本可在本地 `legacy/cpp/` 中保留，用于回溯。该目录已被 Git 忽略，不随仓库发布；当前 Node.js 版本不依赖这些文件。
